## AI가 물어서 내가 정한 것

두 AI에 적용할 웹페이지 기획을 위해 ChatGPT와 질문·답변을 진행하며 다음 내용을 결정했다.

- **누가 쓰나:** 나뿐 아니라 다른 사람도 사용할 수 있고, 각자 만든 티어리스트를 비교한다. PC와 휴대폰 모두 지원한다.
- **무엇을 하려고:** 친구들과 재미로 영화를 S·A·B·C·D·F의 여섯 등급으로 분류하고 평가 차이를 확인한다. 같은 등급 안에서는 별도 순위를 매기지 않는다.
- **화면과 동작:** 영화관 분위기의 어두운 디자인을 사용한다. 닉네임 입력 후 내 티어리스트로 들어간다. 영화는 포스터와 제목을 함께 보여주며, 드래그 또는 클릭으로 등급을 정한다. 미평가 영화는 화면 아래 미분류 목록에 둔다. 친구 닉네임 검색 후 티어리스트를 나란히 보거나 영화별 등급 비교 화면으로 전환한다. 한 사람만 평가한 영화도 비교 화면에 표시하고, 결과를 PNG로 저장할 수 있게 한다.
- **계정과 저장:** 중복 닉네임은 허용하지 않고 닉네임·비밀번호를 사용한다. 비밀번호는 복구 코드로 재설정한다. 사용자당 티어리스트는 하나이며, 변경 사항은 즉시 자동 저장한다. 원래 목표는 PC와 휴대폰에서 같은 기록을 사용하는 것이었다.
- **필요한 자료:** TMDB를 통해 한국·해외 영화를 검색하고, 기본 인기 영화 약 50편을 제공한다. 새 영화는 개수 제한 없이 추가한다.
- **완성 기준:** 누구나 인터넷으로 접속할 수 있고, 핵심 기능과 디자인이 완성된 웹페이지를 목표로 정했다. 단, 이번 제작 조건은 **서버와 외부 파일 없이 브라우저에서 바로 열리는 단일 HTML 파일**이므로, 원래 기획의 온라인 계정 공유·기기 간 동기화 등은 그대로 구현할 수 없는 제약이 있다.

## 같은 행동으로 비교한 결과

| 해본 행동(비교 기준) | 기대 결과 | A의 결과 | B의 결과 |
|---|---|---|---|
| HTML 파일 하나를 브라우저에서 열기 | 별도 설치 없이 한국어 웹페이지 표시 | HTML 안에 CSS와 JavaScript를 포함한 오프라인 페이지로 구성 | HTML 안에 CSS와 JavaScript를 포함한 오프라인 페이지로 구성 |
| 닉네임과 비밀번호로 계정 만들기 | 닉네임이 중복되지 않고 기록을 구분 | 같은 브라우저의 로컬 저장소를 이용한 계정 및 복구 코드 기능 구현 | 같은 브라우저의 로컬 저장소를 이용한 계정 및 복구 코드 기능 구현 |

| 친구 닉네임을 찾아 비교하기 | 나란히 보기와 영화별 등급 비교 | 같은 브라우저에 저장된 다른 계정끼리 비교하도록 구현 | 같은 브라우저에 저장된 다른 계정끼리 비교하도록 구현. 상대 티어리스트 보기·나란히 비교·영화별 비교 모드 및 영화별 필터 기능 포함 |

## 선택한 파일명과 고른 이유

- **선택한 AI:** B — Claude
- **선택한 파일:** `영화_티어리스트.html`

**B를 선택한 이유:** 두 파일 모두 단일 HTML 형태로 핵심적인 티어 분류와 비교 기능을 구현했지만, B는 내가 처음 기획한 기능에 조금 더 가깝다고 판단했다. 특히 **TMDB API 키를 설정하면 실제 영화 검색과 포스터 표시를 시도할 수 있다는 점**이 가장 큰 차이였다. A는 오프라인 체험에 중점을 두어 내장 영화 목록과 대체 이미지만 제공하는 반면, B는 API 키가 없을 때 기본 영화 목록을 사용할 수 있고 필요하면 기능을 확장할 수도 있다. 또한 B는 **티어 비교 화면의 필터 기능**, **JSON 백업 및 가져오기 기능**을 포함하여 사용성과 데이터 관리 측면에서 더 유용해 보였다. 영화관 느낌의 어두운 색상과 등급별 색상 구분도 내가 정한 디자인 방향에 맞았다.

다만 B가 기획서를 완전히 구현한 것은 아니다. TMDB 기능은 **인터넷 연결 및 사용자 API 키가 있어야 작동**하며, 데이터는 서버가 아닌 **브라우저 로컬 저장소**에 저장된다. 따라서 다른 기기와의 자동 동기화, 인터넷상 다른 사용자의 실시간 검색과 공유는 지원하지 않는다. 이 한계를 이해한 상태에서, 이번 과제의 **단일 HTML 파일** 조건에 더 적합한 선택으로 B를 골랐다.

## 수정 여부

**수정하지 않음.** 제출 파일은 Claude가 생성한 `영화_티어리스트.html` 원본으로 선택했다.

| 파일명 | 고친 내용 | 고친 이유 | 다시 확인한 결과 |
|---|---|---|---|
| 해당 없음 | 수정하지 않음 | 이번 미션에서는 AI별 생성 결과를 원본 그대로 비교하고, 더 적합한 결과물을 선택하기로 함 | B 파일의 주요 기능을 소스코드로 확인했고 JavaScript 구문 검사 통과. 전체 브라우저 동작 시험은 별도로 수행하지 않음 |

- **고치지 않았다면 그대로 둔 이유:** B가 핵심 목표인 영화 등급 분류, 자동 저장, 친구 비교, PNG 저장 기능을 갖추고 있고, A보다 영화 검색·포스터 활용과 데이터 이전 기능이 확장되어 있어 현 단계에서 별도 수정 없이 선택하기에 충분하다고 판단했다. 또한 두 AI의 결과물을 임의로 수정하지 않고 원본 상태로 비교하려는 목적도 있었다. 남은 온라인 동기화 제약은 HTML의 단순한 문구 수정으로 해결되는 문제가 아니어서 이번 수정 범위에 포함하지 않았다.

- **(선택) 코랩에서 함께 이야기하고 싶은 내용과 그 이유:** 서버 없이 HTML 파일 하나만 만들라는 조건에서 **원래 기획의 온라인 친구 검색·기기 간 동기화를 어디까지 대체 구현하는 것이 적절한지** 이야기해 보고 싶다. 같은 요구사항을 주더라도 AI마다 오프라인 중심 구현(A)과 API를 활용한 확장 가능 구현(B)처럼 접근이 달랐기 때문이다.
